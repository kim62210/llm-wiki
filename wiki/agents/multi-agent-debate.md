# 멀티에이전트 디베이트 (Multi-Agent Debate)

여러 LLM 에이전트가 동일한 문제에 대해 각자 초기 답변을 제시한 뒤 상호 비판과 반박을 거쳐 최종 합의에 수렴하는 집단 추론 패턴. 단일 모델의 편향을 교정하고 추론 품질을 높이는 것이 핵심 목적이다.

## 왜 중요한가

단일 LLM은 자신의 초기 답변을 고집하는 경향(sycophancy)과 추론 오류를 자기 점검하지 못하는 한계가 있다. 2023년 Du et al.의 연구에서 "Society of Mind" 방식으로 여러 모델이 토론하면 수학 추론과 전략적 추론에서 단독 모델 대비 유의미한 성능 향상이 확인됐다. 이 패턴은 인간의 집단 지성(collective intelligence)을 LLM 시스템으로 구현한 시도이기도 하다.

## 라운드 구조

```mermaid
flowchart TD
    Q[질문 / 문제] --> A1[에이전트 A\n초기 답변]
    Q --> A2[에이전트 B\n초기 답변]
    Q --> A3[에이전트 C\n초기 답변]

    A1 & A2 & A3 --> R1{디베이트 라운드 1}
    R1 --> C1[A가 B, C를 비판]
    R1 --> C2[B가 A, C를 비판]
    R1 --> C3[C가 A, B를 비판]

    C1 & C2 & C3 --> R2{디베이트 라운드 2}
    R2 --> U1[A 답변 갱신]
    R2 --> U2[B 답변 갱신]
    R2 --> U3[C 답변 갱신]

    U1 & U2 & U3 --> J[판정자(Judge) 에이전트\n또는 다수결 집계]
    J --> Ans[최종 답변]
```

라운드 수는 보통 2~3회로 제한한다. 무한 반복을 막기 위해 수렴 기준(답변 간 유사도 임계값 초과 시 종료)이나 최대 라운드 수를 설정한다.

## 핵심 역할

| 역할 | 설명 |
|------|------|
| **제안자(Proposer)** | 초기 답변 생성. 복수의 에이전트가 각각 독립 생성 |
| **비판자(Critic)** | 다른 에이전트의 답변에서 논리적 오류, 사실 오류, 누락된 관점을 지적 |
| **조정자(Moderator)** | 토론 흐름 관리, 반복 제한, 수렴 판단 |
| **판정자(Judge)** | 최종 라운드 후 모든 답변을 종합해 최종 결론 도출 |

한 에이전트가 여러 역할을 순차적으로 수행하는 구현도 가능하다.

## 합의 전략

**다수결(Majority Voting)**: 마지막 라운드에서 각 에이전트의 답변 중 가장 많이 등장한 것을 선택. 구현이 단순하고 편향 개입이 적다.

**판정자 요약(Judge Summary)**: 전문 "Judge" 에이전트가 모든 논쟁을 검토하고 종합 결론을 도출. 품질이 높지만 판정자 자체의 편향이 전이될 수 있다.

**가중 투표(Weighted Voting)**: 에이전트별로 신뢰도 가중치를 부여. 특정 도메인에 강한 모델의 의견을 더 반영할 수 있다.

## [[orchestrator-worker-pattern]]과의 차이

[[orchestrator-worker-pattern]]은 오케스트레이터가 태스크를 분해해 워커에게 위임하는 **분업** 구조다. 멀티에이전트 디베이트는 동일한 태스크에 대해 에이전트들이 **경쟁적으로 검토**하는 구조다. 두 패턴은 결합 가능하다: 오케스트레이터가 어려운 서브태스크를 디베이트 클러스터에 위임하는 방식이 대표적이다.

## 비용-성능 트레이드오프

디베이트는 에이전트 수 x 라운드 수만큼 LLM 호출이 증가한다. 에이전트 3개, 라운드 2회 기준으로 최소 7~9회 호출이 필요하다(초기 생성 3 + 비판 3 + 갱신 3). 비용 대비 효과가 가장 높은 구간은 **수학적 추론, 사실 확인, 코드 정확성 검증** 태스크다. 단순한 창의적 글쓰기에는 오히려 균질화가 일어나 적합하지 않다.

## 실무 구현 고려사항

- **에이전트 다양성**: 같은 모델을 사용하면 동일한 편향을 공유하므로 효과가 제한된다. 서로 다른 시스템 프롬프트(역할 페르소나)나 다른 모델을 혼합하는 것이 권장된다.
- **비판 포맷**: "무엇이 틀렸는지" + "어떻게 개선할 수 있는지"를 구조화된 형식으로 요청하면 비판의 질이 높아진다.
- **에코 챔버 방지**: 에이전트들이 초기 다수 의견에 무비판적으로 동조하지 않도록 "반드시 적어도 한 가지 비판을 포함해야 한다"는 제약을 두는 것이 효과적이다.
