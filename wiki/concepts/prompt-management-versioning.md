## 개요

프롬프트 관리와 버전 관리(Prompt Management & Versioning)는 프로덕션 LLM 시스템에서 프롬프트를 체계적으로 추적, 관리, 배포하는 실천 체계다. LLM의 비결정론적 특성 때문에 프롬프트의 사소한 수정도 출력에 큰 영향을 미칠 수 있으므로, 프롬프트 변경을 모델 코드 변경과 동일한 수준의 엄격함으로 관리해야 한다. [[model-lifecycle-management|모델 수명주기 관리]]의 핵심 구성요소이며, 2024년 분석에 따르면 AI 파일럿 프로그램의 95%가 측정 가능한 효과를 내지 못하는데, 관리되지 않는 프롬프트 변경이 이 실패율에 상당히 기여한다.

## 핵심 원칙

**불변성(Immutability)**: 프롬프트 버전이 생성되면 수정되지 않는다. 변경이 필요하면 새 버전을 생성한다. 프로덕션 로그를 분석할 때 특정 트레이스 ID를 프롬프트 v4.2에 연결했을 때, v4.2가 로그 생성 이후 변경되지 않았음을 확신할 수 있다.

**분리(Decoupling)**: 프롬프트를 애플리케이션 코드에서 분리하여, 코드 재배포 없이 프롬프트를 업데이트하거나 롤백할 수 있게 한다. 프롬프트 레지스트리(Registry)에 중앙 관리하여 핫픽스와 즉시 롤백을 가능하게 한다.

**민주화(Democratization)**: 프롬프트 레지스트리의 UI를 통해 비기술 이해관계자(프로덕트 매니저, 도메인 전문가 등)도 프롬프트를 조회하고 편집할 수 있게 한다. 단, 프로덕션 배포에는 적절한 승인 워크플로우를 적용한다.

## 프롬프트 수명주기

### 1. 작성과 반복

프롬프트 엔지니어가 초기 프롬프트를 작성하고, 평가 데이터셋을 통해 성능을 측정하며 반복적으로 개선한다. 각 반복이 새로운 버전으로 기록된다.

### 2. 평가와 비교

A/B 테스트, 오프라인 평가, LLM-as-judge 등을 통해 프롬프트 버전 간 성능을 비교한다. [[ai-observability-patterns|관측성 체계]]와 연계하여 각 버전의 품질, 비용, 지연 시간을 정량적으로 비교한다.

### 3. 환경별 배포

개발(dev) -> 스테이징(staging) -> 프로덕션(production) 환경을 통한 단계적 배포를 구현한다. 각 환경에서 독립적으로 프롬프트 버전을 지정할 수 있다.

### 4. 모니터링과 롤백

프로덕션에서 [[ai-observability-patterns|관측성 데이터]]를 통해 프롬프트 성능을 지속적으로 모니터링한다. 성능 저하가 감지되면 이전 안정 버전으로 즉시 롤백한다. [[ai-incident-response|장애 대응]] 시 프롬프트 롤백은 가장 빠른 복구 수단 중 하나다.

## 프롬프트 레지스트리

프롬프트 레지스트리는 모든 프롬프트 버전을 중앙에서 저장하고 관리하는 시스템이다. 모델 레지스트리(MLflow Model Registry 등)와 유사한 개념이지만 프롬프트에 특화되어 있다.

핵심 기능은 다음을 포함한다: 버전 이력과 변경 사항 추적, 환경별 배포 관리(dev/staging/prod), 프롬프트 템플릿과 변수 관리, 접근 제어와 승인 워크플로우, 평가 결과와의 연동, [[token-economics|토큰 사용량]] 추적이다.

**MLflow Prompt Registry**: MLflow가 2025년에 도입한 프롬프트 전용 레지스트리. 기존 MLflow 모델 레지스트리와 통합되어 모델-프롬프트 조합의 전체 이력을 관리할 수 있다.

## 코드 기반 vs 플랫폼 기반 관리

**코드 기반(Git 관리)**: 프롬프트를 코드 저장소에서 텍스트 파일로 관리한다. Git의 버전 관리, 코드 리뷰, CI/CD 파이프라인을 그대로 활용할 수 있다. 개발자 친화적이지만, 비기술 이해관계자의 접근이 어렵고 핫픽스에 코드 배포가 필요하다.

**플랫폼 기반(레지스트리)**: 전용 프롬프트 관리 플랫폼에서 UI를 통해 관리한다. 즉시 업데이트와 롤백이 가능하고 비기술 이해관계자도 참여할 수 있다. 추가 인프라 비용과 복잡성이 발생한다.

실무에서는 두 접근법을 결합하는 경우가 많다. Git을 진실의 원천(source of truth)으로 유지하면서, CI/CD 파이프라인이 변경사항을 프롬프트 레지스트리에 동기화하는 방식이다.

## 프롬프트 버전 관리와 [[batch-inference-caching|캐싱]]의 연계

프롬프트 버전이 변경되면 기존 프롬프트 캐시가 무효화된다. 이 연관성을 [[ai-observability-patterns|관측성 체계]]에서 추적하여, 프롬프트 변경이 캐시 적중률과 [[token-economics|비용]]에 미치는 영향을 정량적으로 측정해야 한다.
