# 바이브 코딩 환자 관리 앱 보안 참사

의료 전문가가 AI 코딩 에이전트로 환자 관리 시스템을 만들어 배포한 뒤 발견된 보안 참사 사례. [[vibe-coding|바이브 코딩]]의 위험성을 극단적으로 보여주는 사례다.

## 배경

의료 전문가가 AI 코딩 영상에 영감을 받아, 기존 솔루션 대신 코딩 에이전트로 환자 관리 시스템을 직접 제작. 완성 후 인터넷에 배포하고 모든 기존 환자 데이터를 입력했다.

## 발견된 취약점 (테스트 30분 이내)

| 취약점 | 심각도 | 설명 |
|--------|--------|------|
| 전체 데이터 노출 | Critical | 모든 환자 데이터에 대한 완전한 읽기/쓰기 접근. 암호화 없이 오픈 인터넷에 노출 |
| 클라이언트사이드 인증 | Critical | 모든 접근 제어가 JavaScript에만 존재. 기본 명령어로 데이터 탈취 가능 |
| DB 보안 부재 | Critical | 매니지드 DB 서비스에 접근 제어 미설정, row-level security 없음 |
| 무단 데이터 전송 | High | 음성 녹음이 동의 없이 외부 AI API로 직접 전송 |

## 기술적 실체

**전체 애플리케이션이 단일 HTML 파일**. 모든 JavaScript, CSS, 구조가 인라인으로 작성. 백엔드 보안은 사실상 부재하며, 프론트엔드 난독화에만 의존.

## 규정 위반

- **nDSG(스위스 데이터 보호법)** 위반
- 직업적 비밀유지 의무 잠재적 위반
- 미국 서버에 민감 의료 정보 저장 (DPA 없이)

## 교훈

저자의 핵심 메시지:
> "나도 AI 코딩 에이전트를 사용하지만, 무슨 일이 일어나고 있는지 이해할 수 있고, 코드를 읽을 수 있다."

### [[vibe-coding|바이브 코딩]]과 [[relocating-rigor|리고어 재배치]]의 교차점

이 사례는 [[vibe-coding|바이브 코딩]]의 "코드를 리뷰하지 않는" 특성이 보안 민감 도메인에서 어떻게 재앙으로 이어지는지 보여준다. [[relocating-rigor|리고어 재배치]] 관점에서, 코딩 자체의 노력이 줄었더라도 **보안 검토, 아키텍처 판단, 규정 준수 확인**이라는 리고어는 여전히 누군가가 담당해야 한다.

### 안티패턴 체크리스트

- 기술 배경 없이 AI로 민감 시스템 구축
- 보안 리뷰 없이 프로덕션 배포
- 클라이언트사이드 전용 인증
- 규정 준수 미확인
- 외부 API로의 무단 데이터 전송
