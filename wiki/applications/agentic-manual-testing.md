# Agentic Manual Testing

Simon Willison이 [[agentic engineering guide]] Section 3에서 다루는 수동 테스트 자동화 패턴.

## 핵심 원칙

> "Never assume that code generated by an LLM works until that code has been executed."

> "Just because code passes tests doesn't mean it works as intended."

자동 테스트가 있어도 서버 크래시, 누락된 UI 요소, 테스트가 커버하지 못한 디테일이 있다. **수동 테스트는 여전히 필수**다. 차이점은 이제 *에이전트가* 수동 테스트를 수행할 수 있다는 것이다.

## 언어별 Manual Testing 기법

### Python 라이브러리

`python -c "... code ..."`로 파이썬 인터프리터에 코드를 직접 전달.

예: import 포함한 짧은 스니펫을 인라인 실행. 에이전트는 이 트릭을 알고 있는 경우가 많지만, 상기시켜주면 효과적.

### 다른 언어

에이전트에게 `/tmp`에 데모 파일을 쓰게 하고, 컴파일 및 실행시켜 엣지 케이스 검증.

### Web API

- JSON API는 `curl`로 exercise
- 개발 서버를 띄우고 여러 요청 보내기
- "explore" 지시어를 주면 에이전트가 API의 여러 측면을 탐색

### 문제 발견 시

수동 테스트가 문제를 드러내면 → 이후 [[red-green TDD]]로 수정 → 영구적 테스트 커버리지 확보

## 브라우저 자동화 (Web UI 테스트)

복잡한 웹 UI를 에이전트가 직접 조작하게 하는 것이 가능.

### [[Playwright]]

> "Most powerful browser automation tool"

- Microsoft의 오픈소스 라이브러리
- 다언어 바인딩
- 주요 브라우저 엔진 제어

### agent-browser (Vercel)

코딩 에이전트용으로 특별히 설계된 CLI 래퍼.

### [[Rodney]]

Simon Willison 본인의 프로젝트:
- Chrome DevTools Protocol로 Chrome을 직접 제어
- `uvx rodney --help`로 설치 트리거
- 에이전트에게 "look at screenshots"로 vision 능력 활용
- JavaScript 실행, 스크롤, 클릭, 타이핑, accessibility tree 읽기

### 사용 패턴 예

에이전트에게 제공하는 프롬프트 요소:
- `uvx rodney --help` 실행 → 자동 설치
- 스크린샷 캡처 요청 → LLM의 멀티모달 능력 활용
- JavaScript evaluate → DOM 직접 검사

브라우저 자동화 테스트를 에이전트가 유지보수하면, 디자인 변경에 따른 마찰이 크게 줄어든다.

## [[Showboat]]로 수동 테스트 흐름 문서화

Showboat = 코딩 에이전트가 자신의 작업을 시연하는 문서를 작성하도록 돕는 도구.

세 가지 핵심 커맨드:

| 커맨드 | 역할 |
|--------|------|
| `note` | Markdown 노트 추가 |
| `exec` | 명령 + 실행 결과를 기록 (결과 위조 억제) |
| `image` | 이미지 추가 (예: Rodney 스크린샷) |

`exec`의 중요성: 명령과 실제 출력을 같이 기록하므로, 에이전트가 결과를 "만들어내는" 위험을 줄인다. Simon은 이 점을 특히 강조한다.

## 왜 수동 테스트가 여전히 중요한가

Simon의 논리:
- 자동 테스트는 **알려진 시나리오**만 커버
- 수동 테스트는 "뭔가 이상한" 것들을 잡는다
- 에이전트가 대신 수동 테스트를 할 수 있으므로 이제 부담이 현저히 낮아짐
- 발견된 문제는 다시 자동 테스트로 굳힌다 ([[red-green TDD]])

## 실무 통합

1. 기능 완성 직후 → "Use rodney to manually test this feature, take screenshots, then fix what you find"
2. 문제 발견 → 자동 테스트로 고정 → 영구 회귀 방지
3. Showboat로 테스트 플로우 문서화 → PR에 첨부 → [[anti-patterns in agentic engineering|리뷰어에게 증거 제공]]
