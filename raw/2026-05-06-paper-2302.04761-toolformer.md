## Abstract

> Language models (LMs) exhibit remarkable abilities to solve new tasks from just a few examples or textual instructions, especially at scale. They also, paradoxically, struggle with basic functionality, such as arithmetic or factual lookup, where much simpler and smaller models excel. In this paper, we show that LMs can teach themselves to use external tools via simple APIs and achieve the best of both worlds. We introduce Toolformer, a model trained to decide which APIs to call, when to call them, what arguments to pass, and how to best incorporate the results into future token prediction. This is done in a self-supervised way, requiring nothing more than a handful of demonstrations for each API. We incorporate a range of tools, including a calculator, a Q\&A system, a search engine, a translation system, and a calendar. Toolformer achieves substantially improved zero-shot performance across a variety of downstream tasks, often competitive with much larger models, while not sacrificing its core language modeling abilities.

(Source: arxiv.org/abs/2302.04761)

## 핵심 기여

1. **자기지도 학습 기반 도구 사용** — 사람 라벨 없이 LM 스스로 API 호출 데이터를 생성
2. **5개 도구 통합** — Calculator, Q&A (Atlas), Search (Wikipedia), Translation (NLLB), Calendar
3. **Loss-based filtering** — API 호출이 next-token prediction loss를 줄였을 때만 학습 데이터로 채택
4. **GPT-J 6.7B가 GPT-3 175B와 경쟁** — 도구 사용으로 작은 모델이 큰 모델 따라잡음
5. **언어 모델링 능력 유지** — 도구 사용 학습이 일반 LM 성능을 해치지 않음

## 방법론

- **Step 1: Sampling** — 각 API에 대해 in-context로 몇 개의 demonstration을 주고, 본문에 API 호출 후보 위치를 LM이 직접 표시
- **Step 2: Executing** — API를 실제로 호출
- **Step 3: Filtering** — API 응답을 prefix에 포함했을 때 next-token loss가 줄어드는 후보만 채택
  - 임계값 $\tau$ 이상 loss 감소가 있어야 학습 데이터로 사용
- **Step 4: Fine-tuning** — 채택된 데이터로 LM을 standard LM loss로 fine-tune
- 추론 시: 모델이 `[API(args) → result]` 형태로 API 호출을 자연스럽게 생성

## 결과/실험

- **LAMA (factual)**: Toolformer 53.5 vs GPT-J 17.6 (Wikipedia 검색 도구 활용)
- **Math (ASDiv, SVAMP, MAWPS)**: 큰 폭 개선 (Calculator 활용)
- **TempLama**: Calendar 도구로 시간 의존 fact 정확도 향상
- **MLQA**: Translation 도구로 다국어 QA 향상
- **Counterfactuals**: 도구 학습 후에도 일반 LM perplexity 보존

## 하네스 엔지니어링 관점

- **도구 사용 능력은 학습으로 내재화 가능** — prompt-only 방식(ReAct)과 학습 방식의 trade-off
- **Loss-reduction filtering의 묘미** — 도구가 도움 됐는지 자동 판정. harness에서도 "이 tool call이 task를 진전시켰는가"를 평가하는 패턴으로 응용 가능
- **단일 시점 호출** — Toolformer는 한번 결과를 받으면 컨텍스트에 통합하고 끝. 멀티 스텝 도구 사용은 ReAct/SWE-agent류 prompt loop에 의존
- **Tool 정의 비용** — 각 도구마다 demonstration + filtering pipeline 설계 필요
- 현대 OpenAI/Anthropic function calling은 prompt-time tool selection 위주 — Toolformer 같은 학습 기반 접근은 주로 도메인 특화 모델(LLaMA-tool, Tool-LLaMA)에서 활용

## 한계/후속연구

- **도구 간 chaining 불가** — 한 단계 도구 호출만 자연스럽게 학습됨
- **Loss filter 임계값 민감도** — $\tau$ 선택이 결과 데이터 품질에 영향
- **새 도구 추가 시 재학습** — prompt-only 접근에 비해 유연성 떨어짐
- 후속: Tool-LLaMA, Gorilla, ChatGPT plugins (런타임 정의), GPT-4 function calling
